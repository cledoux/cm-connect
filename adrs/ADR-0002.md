# ADR-0002: Flag Parsing and Passthrough Strategy for Subprocess Execution

- **Status:** accepted
- **Date:** 2026-08-17
- **Decision Makers:** Charles LeDoux (ledoux@google.com)

**Shortlink:** go/cm-connect-adr-0002

## Context and Problem Statement

In `cm-connect`, the Go entrypoint binary (`cm-runner`) serves as a lightweight,
sub-millisecond dispatcher and orchestrator for CodeMender (`cm`) CLI
subprocesses.

The `find` workflow is a two-phase coordinated pipeline: scanning
(`/usr/local/bin/cm find`) followed by structured report synthesis
(`/usr/local/bin/cm report --format=<fmt>`). In previous designs, the runner
attempted to treat `--format` as a passthrough flag intended for `cm`, requiring
the runner to intercept and strip it from the argument list so `cm find` would
not reject it. This created ambiguous help menus and required special-case flag
extraction logic.

To simplify the architecture and establish an intuitive, robust CLI contract:

1. **Exact Subcommand Dispatch (`os.Args[1]`):** `cm-runner` does not perform
   any leading `cm` prefix stripping. Invocations such as
   `docker run <image> cm find` are treated as errors
   (`unrecognized subcommand 'cm'`). `os.Args[1]` is strictly required to be the
   target subcommand (`find`, `shell`).
1. **First-Class Wrapper Flag (`--format` on `find`):** Output format
   (`--format`, `-f`) is formally declared as an explicit, first-class option of
   the `cm-runner find` wrapper command, which owns the report synthesis phase.
1. **Clean `--` Partitioning:** The CLI contract is cleanly split around the
   POSIX `--` delimiter:
   `cm-runner find [--format=<fmt>] [path] [-- <cm-find-flags...>]`
   - **Before `--` (Wrapper Domain):** Handled by standard Go `flag.FlagSet`
     containing wrapper-owned flags (`--format`, `-f`, `--help`) and positional
     target path.
   - **After `--` (Subprocess Domain):** Pure, unparsed argument vector
     forwarded verbatim to `cm find` (`-c 5`, `-y`, `--unrestricted`).

How should `cm-connect` implement this simplified, standard-library-driven flag
parsing and passthrough strategy?

## Decision Drivers

- **Zero Custom Token Parsing Hacks:** Eliminate manual string slicing, prefix
  matching, and regexes; rely entirely on Go's standard library `flag.FlagSet`.
- **First-Class CLI Ergonomics & Clean Help:** Provide clean, self-documenting
  help menus (`cm-runner find --help`) that clearly present wrapper options
  (`--format`) without confusing them with underlying `cm` subprocess flags.
- **Strict Boundary Separation via `--`:** Deterministically partition
  wrapper-level arguments from unowned subprocess flags forwarded to `cm find`.
- **Subprocess Argument Integrity:** Guarantee that arbitrary, unowned `cm`
  flags passed after `--` are forwarded to `cm find` in verbatim sequence
  without schema leakage or token mutation.
- **Minimal Dependencies & Fast Startup:** Keep `go.mod` completely
  dependency-free, ensuring instantaneous ~1ms startup latency and zero supply
  chain risk.

## Considered Options

- **Option 1: First-Class Wrapper Flag on `find` with stdlib `flag.FlagSet` and
  `--` Partitioning (Chosen)** — Declare `--format` / `-f` directly on the
  `flag.FlagSet` for the `find` subcommand. Arguments before `--` are parsed by
  `flag.FlagSet` to extract format and positional target path; all tokens after
  `--` are forwarded directly to `cm find`.
- **Option 2: Special-Case Custom Token Extractor (`pkg/cmrunner/flagscan`)** —
  Treat `--format` as a subprocess flag and write a custom lexical scanner to
  intercept and extract it from arbitrary argument positions. (Rejected: adds
  unnecessary code complexity and produces confusing `--help` menus because
  `cm find` does not natively accept `--format`).
- **Option 3: Third-Party POSIX Flag Library (`spf13/pflag`)** — Adopt `pflag`
  with `UnknownFlags=true`. (Rejected: adds external dependencies and suffers
  from space-separated flag-value splitting issues with unowned flags like
  `-c 5`).

## Decision Outcome

Chosen option: **Option 1: First-Class Wrapper Flag on `find` with stdlib
`flag.FlagSet` and `--` Partitioning**.

### Justification

By recognizing that `cm-runner find` is our own high-level command that owns the
output synthesis stage, making `--format` an explicit wrapper flag resolves all
architectural tension:

1. **Standard Library `flag.FlagSet` Does Everything:**
   - A `flag.NewFlagSet("find", flag.ContinueOnError)` declares `-format` and
     `-f` string flags defaulting to `"json"`.
   - `fs.Parse(beforeDash)` parses wrapper flags and extracts any positional
     target path from `fs.Args()`.
   - `afterDash` represents the untouched arguments forwarded directly to
     `cm find`.
1. **Zero Custom Parser Code:**
   - Completely eliminates the need for a custom lexical token scanner, regexes,
     or `strings.HasPrefix` slicing loops.
1. **Clean Help Menus:**
   - Running `cm-runner find --help` natively prints:
     ```
     Usage: cm-runner find [--format=<fmt>] [path] [-- <scan flags>]

     Flags:
       -f string
             output format (json, sarif, table, html, md) (default "json")
       -format string
             output format (json, sarif, table, html, md) (default "json")
     ```
1. **Zero External Dependencies:**
   - Preserves an empty `go.mod`, instantaneous execution, and hermetic builds.

### Consequences

- **Good, because** it eliminates all custom flag parsing and token stripping
  logic across the entire codebase.
- **Good, because** it uses the Go standard library (`flag.FlagSet`)
  exclusively, keeping `go.mod` zero-dependency.
- **Good, because** `cm-runner find --help` generates clean, intuitive usage
  instructions.
- **Good, because** arguments passed after `--` are forwarded to `cm find`
  verbatim without modification or schema ambiguity.
- **Good, because** `os.Args[1]` is strictly the subcommand, rejecting `cm`
  prefixes with clear error messages.
- **Neutral, because** users passing scan-specific flags to `cm find` (such as
  `-c 5` or `--unrestricted`) are encouraged to use the standard `--` delimiter
  (`cm-runner find [path] -- [scan flags]`), which aligns with standard POSIX /
  Unix CLI conventions.

### Confirmation

Compliance and correctness will be verified through:

1. **Subcommand Validation Tests:**
   - Invocation with `cm find` returns
     `errInvalidSubcommand: unrecognized subcommand 'cm'`.
   - Invocation with `find` routes directly to find handler.
   - Invocation with `shell` routes directly to shell handler.
1. **Standard FlagSet & `--` Partitioning Tests:**
   - `find --format=sarif src/auth -- -c 5` sets format to `"sarif"`, target to
     `"src/auth"`, and forwards `["-c", "5"]` to `cm find`.
   - `find -f sarif . -- --unrestricted` sets format to `"sarif"` and forwards
     `["--unrestricted"]` to `cm find`.
   - `find src/auth` sets default format `"json"`, target `"src/auth"`, and
     empty scan flags.
   - `find --help` triggers standard help message and exits cleanly.
1. **Statement Coverage Threshold:**
   - Unit tests enforce $\\ge 90%$ statement coverage threshold (`make test`).

## Pros and Cons of the Options

### Option 1: First-Class Wrapper Flag with stdlib `flag.FlagSet` (Chosen)

- **Good, because** 100% standard library with zero external dependencies.
- **Good, because** zero lines of custom token parsing, regexes, or string
  manipulation.
- **Good, because** standard Go `--help` documentation for `--format` / `-f`.
- **Good, because** clean separation between wrapper options and subprocess
  arguments via `--`.
- **Good, because** unowned subprocess flags are preserved verbatim.

### Option 2: Special-Case Custom Token Extractor

- **Good, because** allows `--format` to be placed anywhere without `--`.
- **Bad, because** requires writing and maintaining custom token scanner logic.
- **Bad, because** produces confusing help menus since `cm find` does not
  natively accept `--format`.

### Option 3: Third-Party POSIX Flag Library (`spf13/pflag`)

- **Good, because** POSIX syntax support.
- **Bad, because** breaks unowned space-separated flags (`-c 5`) into unknown
  flag and positional argument.
- **Bad, because** adds external dependencies.
