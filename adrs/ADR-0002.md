# ADR-0002: Flag Parsing and Passthrough Strategy for Subprocess Execution

- **Status:** accepted
- **Date:** 2026-08-17
- **Decision Makers:** Charles LeDoux (ledoux@google.com)

**Shortlink:** go/cm-connect-adr-0002

## Context and Problem Statement

In `cm-connect`, the Go entrypoint binary (`cm-runner`) serves as a lightweight,
sub-millisecond dispatcher and orchestrator for CodeMender (`cm`) CLI
subprocesses.

The `find` workflow is a two-phase coordinated pipeline: scanning
(`/usr/local/bin/cm find`) followed by structured report synthesis
(`/usr/local/bin/cm report --format=json`). In previous designs, the runner
attempted to support format overrides (`--format`, `-f`), which introduced
unnecessary parsing heuristics, ambiguous `--help` outputs, and complexity into
what should be a streamlined, deterministic batch scanner.

To establish the simplest, most robust CLI contract:

1. **Exact Subcommand Dispatch (`os.Args[1]`):** `cm-runner` does not perform
   any leading `cm` prefix stripping. Invocations such as
   `docker run <image> cm find` are treated as errors
   (`unrecognized subcommand 'cm'`). `os.Args[1]` is strictly required to be the
   target subcommand (`find`, `shell`).
1. **Dedicated Structured JSON Output (Zero Format Flags on `find`):** The
   `find` subcommand always emits pure, structured JSON on `stdout`. It does not
   accept or parse format flags (`--format`, `-f`). Phase 2 always invokes
   `cm report --format=json`.
1. **Clean `--` Partitioning:** The CLI contract is cleanly split around the
   POSIX `--` delimiter: `cm-runner find [path] [-- <cm-find-flags...>]`
   - **Before `--` (Wrapper Domain):** The optional positional target path (e.g.
     `src/auth`, defaulting to `.`).
   - **After `--` (Subprocess Domain):** Pure, unparsed argument vector
     forwarded verbatim to `cm find` (`-c 5`, `-y`, `--unrestricted`).

How should `cm-connect` implement this streamlined flag parsing and passthrough
strategy?

## Decision Drivers

- **Maximum Simplicity & Zero Custom Parsing:** Completely eliminate custom
  token scanners, regexes, and complex flag extraction logic.
- **Dedicated Machine-Readable Contract:** Guarantee that `cm-runner find`
  always outputs structured JSON (`[]` of findings) on `stdout` for downstream
  CI gating tools (`jq`, GitHub Actions).
- **Exact Subcommand Contract:** Rely on `os.Args[1]` as the unambiguous
  subcommand selector with zero prefix-stripping heuristics.
- **Strict Boundary Separation via `--`:** Deterministically partition
  wrapper-level arguments (target path) from unowned subprocess flags forwarded
  to `cm find`.
- **Subprocess Argument Integrity:** Guarantee that arbitrary, unowned `cm`
  flags passed after `--` are forwarded to `cm find` in verbatim sequence
  without schema leakage or token mutation.
- **Minimal Dependencies & Instant Startup:** Keep `go.mod` completely
  dependency-free, ensuring instantaneous ~1ms startup latency and zero supply
  chain risk.

## Considered Options

- **Option 1: Fixed JSON Output with Positional Path & `--` Passthrough
  Partitioning (Chosen)** — `find` always invokes `cm report --format=json` and
  takes no format flags. Arguments before `--` define the target path (default
  `.`), and all arguments after `--` are forwarded directly to `cm find`.
- **Option 2: First-Class Wrapper Flag (`--format`) via stdlib `flag.FlagSet`**
  — Declare `--format` / `-f` on a `flag.FlagSet`. (Rejected: adds unnecessary
  complexity; batch `find` is designed exclusively for machine-readable JSON CI
  gating).
- **Option 3: Special-Case Custom Token Extractor (`pkg/cmrunner/flagscan`)** —
  Treat `--format` as a subprocess flag and write a custom lexical scanner.
  (Rejected: over-engineered and unnecessary).

## Decision Outcome

Chosen option: **Option 1: Fixed JSON Output with Positional Path & `--`
Passthrough Partitioning**.

### Justification

This design strips away all unnecessary parsing overhead and provides the
cleanest possible architecture:

1. **Zero Flag Parsing Code:**
   - No `flag.FlagSet`, no custom scanners, and no string-slicing loops.
   - Parsing `find` arguments simply partitions around `--`:
     ```go
     func parseFindArgs(args []string) (targetPath string, scanFlags []string) {
         beforeDash, afterDash := partitionDash(args)
         targetPath = "."
         if len(beforeDash) > 0 {
             targetPath = beforeDash[0]
         }
         return targetPath, afterDash
     }
     ```
1. **Deterministic Output Guarantee:**
   - CI/CD pipelines, PR bots, and shell scripts can rely on `stdout` always
     being a valid JSON array of finding objects.
1. **Clean Help Menus:**
   - Running `cm-runner find --help` natively prints:
     ```
     Usage: cm-runner find [path] [-- <scan flags>]
     ```
1. **Verbatim Passthrough to `cm find`:**
   - Any flag passed after `--` (`-c 5`, `-y`, `--unrestricted`) is forwarded
     directly to `cm find`.

### CLI Contract & Parsing Flow

```
+-----------------------------------------------------------------------------------------------+
| Raw Invocation: cm-runner find ./src/auth -- -c 5 --unrestricted                              |
+-----------------------------------------------------------------------------------------------+
                                                │
                                                ▼
+───────────────────────────────────────────────────────────────────────────────────────────────+
| 1. Subcommand Switch (dispatch.go): os.Args[1] == "find"                                      |
+───────────────────────────────────────────────────────────────────────────────────────────────+
                                                │
                                                ▼
+───────────────────────────────────────────────────────────────────────────────────────────────+
| 2. Partition on '--':                                                                         |
|    • beforeDash = ["./src/auth"] -> targetPath = "./src/auth" (default ".")                   |
|    • afterDash  = ["-c", "5", "--unrestricted"] -> scanFlags                                 |
+───────────────────────────────────────────────────────────────────────────────────────────────+
                                                │
                        ┌───────────────────────┴───────────────────────┐
                        │ (targetPath + scanFlags)                      │ (Fixed: --format=json)
                        ▼                                               ▼
+───────────────────────────────────────────────+   +───────────────────────────────────────────+
| FindCommand (Phase 1)                         |   | ReportCommand (Phase 2)                   |
| Cmd: ["find", "./src/auth", "-c", "5",        |   | Cmd: ["report", "--format=json"]          |
|       "--unrestricted"]                       |   | (stdout payload)                          |
| (stderr progress)                             |   |                                           |
+───────────────────────────────────────────────+   +───────────────────────────────────────────+
```

### Consequences

- **Good, because** it makes command parsing completely trivial and bulletproof.
- **Good, because** `cm-runner find` is guaranteed to emit clean, predictable
  JSON on `stdout` without format negotiation overhead.
- **Good, because** `go.mod` remains empty with zero third-party dependencies.
- **Good, because** `os.Args[1]` is strictly the subcommand, rejecting `cm`
  prefixes with clear error messages.
- **Good, because** arguments passed after `--` are forwarded to `cm find`
  verbatim without modification or schema ambiguity.

### Confirmation

Compliance and correctness will be verified through:

1. **Subcommand Validation Tests:**
   - Invocation with `cm find` returns
     `errInvalidSubcommand: unrecognized subcommand 'cm'`.
   - Invocation with `find` routes directly to find handler.
   - Invocation with `shell` routes directly to shell handler.
1. **Target Path & `--` Partitioning Tests:**
   - `find src/auth -- -c 5` sets target to `"src/auth"` and forwards
     `["-c", "5"]` to `cm find`.
   - `find . -- --unrestricted` sets target to `"."` and forwards
     `["--unrestricted"]` to `cm find`.
   - `find src/auth` sets target `"src/auth"` and empty scan flags.
   - `find` defaults to `.` and empty scan flags.
   - Phase 2 report always executes `cm report --format=json`.
1. **Statement Coverage Threshold:**
   - Unit tests enforce $\\ge 90%$ statement coverage threshold (`make test`).

## Pros and Cons of the Options

### Option 1: Fixed JSON Output with Positional Path & `--` Partitioning (Chosen)

- **Good, because** zero flag parsing overhead and zero dependencies.
- **Good, because** clean, predictable JSON contract for CI/CD gating.
- **Good, because** completely eliminates parser edge cases and format flag
  mangling.
- **Good, because** unowned subprocess flags are preserved verbatim.

### Option 2: First-Class Wrapper Flag (`--format`) via `flag.FlagSet`

- **Good, because** allows format override on `find`.
- **Bad, because** adds wrapper flag handling when batch `find` is primarily
  designed for automated JSON analysis.

### Option 3: Special-Case Custom Token Extractor

- **Good, because** allows format flag anywhere in argv.
- **Bad, because** requires maintaining custom token scanner logic for a flag
  that `cm find` does not accept.
